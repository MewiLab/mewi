# ADR-012: Mewi Report Raw-To-Value Data Contract

- **Status:** Proposed
- **Date:** 2026-05-29
- **Scope:** `mewi-unity/app/Assets/Scripts/AgentIntegration/Report/**`, `mewi-backend/app/api/routes/report_router.py`, `mewi-report/pipeline/scripts/process.py`, `mewi-report/src/pages/user/report/[userId].astro`

## Context

`mewi-report` builds a static Astro report from JSON files generated by the
Python pipeline:

```text
Unity raw session JSON
  -> mewi-report/pipeline/scripts/process.py
  -> pipeline/processed_data/report_{user_id}.json
  -> src/data/report_{user_id}.json
  -> Astro report pages
```

The website reads processed "value" data: trust arcs, radar percentages,
attention percentages, attachment profile rows, attachment analysis text, and
timeline rows. Those values are derived from raw player/cat behavior logs.

Unity should therefore export factual session traces only. Python owns the
interpretation layer so the same raw logs can be reprocessed when scoring rules
or report copy change.

## Decision

Unity sends one raw JSON file per completed session to FastAPI:

```http
POST /api/v1/report/session
```

FastAPI is the only layer that touches storage or infra. Locally it writes the
validated payload to:

```text
mewi-report/pipeline/raw_data/sessions/{user_id}/{session_id}.json
```

Later this same route can write to S3 without changing Unity. The current
Python processor groups immutable session files by `user_id` before deriving
report values. It still accepts legacy aggregate files under
`pipeline/raw_data/*.json` as a migration fallback.

The current Python processor already ignores unknown top-level and event fields,
so Unity may include additional factual telemetry under `params` or `meta`
without breaking the pipeline.

Unity must not write processed report fields such as `summary`, `radar`,
`attention_pct`, `attachment_profile`, `attachment_analysis`, `timeline`, or
`cats.*.bars`. Those are Python-owned value data.

`report_overrides` remains a local demo escape hatch for hand-curated sample

## Minimal JSON Schema

This schema is intentionally strict about the fields Python needs and loose
about factual extension fields under `source`, `params`, and `meta`.

## Required Fields

Top-level:

| Field | Type | Notes |
|---|---|---|
| `schema_version` | string | Use `mewi.report.raw.v1`. Optional for current code, required for the contract. |
| `user_id` | string | Stable internal ID. Used for `report_{user_id}.json`. |
| `source` | object | Optional factual exporter metadata. Python may ignore it. |
| `session` | object | One completed immutable session. Python groups these by `user_id`. |

Session:

| Field | Type | Notes |
|---|---|---|
| `session_id` | string | Stable session/event grouping key. |
| `session_index` | integer | 1-based order used in report copy and charts. |
| `timestamp_start` | ISO-8601 string | Python uses the date prefix for `meta.last_seen`. |
| `duration_seconds` | number | Factual session length. |
| `events` | array | Chronological behavior events. Required. |
| `multi_cat_encounters` | array | Optional rows for the encounter table. |

Event:

| Field | Type | Notes |
|---|---|---|
| `t` | number | Seconds since `timestamp_start`; events must be sorted ascending. |
| `actor` | `"human"` or `"cat"` | Determines which processor path reads the event. |
| `action` | string | Canonical snake_case action name. |
| `params` | object | Optional factual details; safe place for Unity-specific telemetry. |
| `cat_id` | string | Required when `actor == "cat"`. Must be one of `mewi`, `miso`, `yuzu`, `haru` for the current report. |
| `trust_before` | integer | Required for cat events when trust changed or is being recorded. Range `0..100`. |
| `trust_after` | integer | Required for cat events that should affect trust arcs. Range `0..100`. |
| `trigger` | string | Optional snake_case cause label shown in sequence logs. |

Encounter:

| Field | Type | Notes |
|---|---|---|
| `t` | number | Seconds since session start. |
| `cats_present` | string array | Cat IDs present at the same decision moment. |
| `human_action` | string | What the player chose while multiple cats were present. |
| `outcome` | string | Factual outcome label. |

## Canonical Action Names

Human action names drive radar and attachment dimensions. Unity should prefer
these names so Python can derive useful values without per-build mapping:

| Human action | Used for |
|---|---|
| `approach` | Approach axis; approach/retreat oscillation. |
| `retreat`, `flee`, `stop_moving` | Retreat axis; approach/retreat oscillation. |
| `offer_item` | Offer item axis; offer-without-demanding-return score. |
| `sit`, `wait`, `crouch` | Wait/dwell axis; patience and zone-dwell scores. |
| `call_out`, `vocalize` | Call out axis. |
| `pet_attempt` | Pet attempt axis; persistence after avoidance. |

## Unity-Derived Human Actions

The player/human actor may use the same creature prefab and motor actions as
NPC cats. In that case `approach` is not a distinct prefab animation. It is a
derived relationship event:

```text
human action = "approach"
when the human-controlled actor's distance to a configured report cat decreases
by at least approachDistanceDeltaMeters while inside approachMaxDistanceMeters.
```

The Unity implementation lives under
`mewi-unity/app/Assets/Scripts/AgentIntegration/Report/`:

- `ReportSessionPayload.cs` contains the raw-report DTOs and serializes a
  `params` field through C#'s escaped `@params` identifier.
- `ReportActionClassifier.cs` maps shared motor intents to report actions.
  `go_to`, `move`, `follow`, and `investigate` become `approach` only when the
  target is a configured report cat.
- `ReportSessionLogger.cs` can also sample distance over time and emit derived
  `approach`, `retreat`, and `wait` events with factual telemetry in `params`
  and provenance in `meta`.
- `ReportSessionSender.cs` sends the same one-session payload to FastAPI. Local
  file export remains only a debug fallback.

Example derived event:

```json
{
  "t": 12.5,
  "actor": "human",
  "action": "approach",
  "params": {
    "zone_id": "harbor_lantern",
    "target_id": "mewi",
    "initiated_by": "derived_proximity",
    "distance_to_nearest_cat_m": 2.4,
    "speed_mps": 0.8
  },
  "meta": {
    "source_system": "proximity_sampler",
    "recorder": "ReportSessionLogger",
    "derivation": "distance decreased by >= 0.35m"
  }
}
```

Cat action names are more open-ended, but these names currently produce the
cleanest derived values:

| Cat action | Used for |
|---|---|
| `sit`, `groom`, `nod_head` | Approach-accepted style trust signals. |
| `eat` | Food-accepted trust signal. Use `params.subtype = "eat_from_hand"` instead of changing the action name. |
| `vocalize` | Vocalized-at-you trust signal. |
| `flee`, `alert` | Caution/zone-entry signal. |
| `bat` | Yuzu provocation signal. |
| `approach`, `settle`, `hold_distance`, `withdraw` | Narrative moments and sequence logs. |

Cat-trigger names are also open-ended. For cat-initiated contact bars, use
`trigger: "cat_initiated"` or `trigger: "proximity_comfort"` when that is the
factual cause.

## Trust Arc Rule

The current processor computes each cat's session trust from the final cat event
for that `cat_id` inside that session:

```text
session trust for cat C = last events[].trust_after where actor == "cat" and cat_id == C
```

Therefore Unity should emit cat events whenever a cat's trust state changes.
If a cat is important to the report for a session, make sure the final event for
that cat carries the final `trust_after` value for that session.

If a session has no cat event for a given report cat, the current processor
records that cat's trust as `0` for that session. Do not omit cat events when
the desired report meaning is "trust held steady."

Trust values are absolute values on a `0..100` scale, not deltas. Dips are
allowed and useful.

## Validation Rules

Before accepting a Unity export into storage, validate:

- `session` is present and has `session_id`, `session_index`,
  `timestamp_start`, `duration_seconds`, and chronological `events`.
- Every event has `t`, `actor`, and `action`.
- Every cat event has `cat_id`, `trust_before`, and `trust_after`.
- `cat_id` is one of the report cats for v1: `mewi`, `miso`, `yuzu`, `haru`.
- Human actions use the canonical names above unless a Python mapping has been
  added.
- Trust values are integers in `0..100`.
- Production exports do not include `report_overrides`.

## Consequences

- Unity remains the source of observed behavior facts.
- Python remains the source of report values and attachment interpretation.
- The Astro website can keep reading one processed report JSON shape.
- The same Unity raw file can be reprocessed when analysis rules change.
- New Unity telemetry should be added under `params` first; promote it to a
  top-level contract field only after Python or the website needs it directly.
